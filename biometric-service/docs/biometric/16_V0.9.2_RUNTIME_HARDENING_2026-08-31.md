# v0.9.2 runtime hardening — 2026-08-31

## Scope

Only `biometric-service/` was changed. No workforce application code and no TiDB schema were changed.

## Real-device evidence inherited from v0.9.1 validation

The ZKTeco SpeedFace-V5L (`AJE1261900133`) successfully demonstrated:

- durable ATTLOG ingest in TiDB;
- canonical punch creation;
- duplicate suppression during terminal retry;
- successful ACK followed by terminal stop-retry behavior;
- `biometric_svc_devices` update;
- `biometric_svc_device_users` update;
- all four durable ingests present as four canonical punches and four `processed` processing rows at the validation checkpoint;
- real fingerprint normalization for `check_in`, `break_out`, and `overtime_in`.

The historical v0.9.0 row with null normalized meanings remains historical evidence and is not rewritten.

## v0.9.2 hardening

1. Due `pending`/`retry` rows are swept while the service runs; restart is no longer required for ordinary canonical retry recovery.
2. Retry state uses idempotent upsert semantics.
3. Device timezone reaches canonical punches and UTC is derived safely when possible.
4. Device runtime policy now uses `status`, `mode`, and `accept_events_from`.
5. Diagnostic logs rotate and retention is bounded.
6. ZKTeco implementation has one canonical vendor path.
7. Direct database dependency is pinned exactly; deployment `npm install` generates the authoritative lockfile.

## Database contract

Unchanged. Runtime DDL remains forbidden and startup schema validation remains read-only.
