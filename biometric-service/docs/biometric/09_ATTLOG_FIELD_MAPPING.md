# ATTLOG Field Mapping — SpeedFace-V5L Compatibility Profile

**Validated:** 2026-08-29  
**Device:** ZKTeco SpeedFace-V5L / `AJE1261900133`  
**Parser baseline:** `zkteco-attlog-observer-v6`

## 1. Observed line shape

All validated attendance samples used ten tab-separated fields:

```text
[0] device_user_id
[1] device_event_time
[2] raw_status
[3] raw_verify
[4] work_code
[5] unknown_1
[6] unknown_2
[7] unknown_3
[8] unknown_4
[9] unknown_5
```

Example:

```text
900001\t2026-08-29 16:45:05\t1\t1\t0\t0\t0\t255\t0\t0
```

Unknown fields stay raw until independently proven.

## 2. rawStatus — proven punch state

| rawStatus | Normalized meaning | Evidence status |
|---:|---|---|
| 0 | `check_in` | real controlled test |
| 1 | `check_out` | real controlled test |
| 2 | `break_out` | real controlled test |
| 3 | `break_in` | real controlled test |
| 4 | `overtime_in` | real controlled test |
| 5 | `overtime_out` | real controlled test |
| 255 | `unspecified` / no selected punch state | observed before punch-state selection |

Do not convert `255` to check-in or check-out.

## 3. rawVerify — proven verification method

| rawVerify | Normalized meaning | Evidence status |
|---:|---|---|
| 1 | `fingerprint` | real controlled test |
| 3 | `password` | real controlled test |
| 4 | `card` | real controlled test |
| 15 | `face` | real controlled + repeat confirmation |
| 25 | `palm` | real controlled test |

No QR mapping is approved.

## 4. Orthogonality

`rawStatus` and `rawVerify` are independent dimensions.

Example:

```text
rawStatus=1 + rawVerify=1
=> check_out performed by fingerprint
```

A future sample could validly be:

```text
rawStatus=1 + rawVerify=15
=> check_out performed by face
```

but that exact combination has not yet been required as a separate protocol proof because both dimensions were independently validated.

## 5. Persistence rule

Any future permanent record should preserve:

```text
raw_status
raw_verify
```

and may additionally store normalized interpretations generated by the adapter:

```text
punch_state
verification_method
```

The normalized values must be treated as derived data; raw values are source evidence.

## 6. Unknown fields

Observed extra fields remained:

```text
["0","0","255","0","0"]
```

across the tested methods/states. Their semantics are **not proven** and must not be named or used in business logic yet.

## 7. Work code

Observed `workCode="0"` in all controlled samples. No semantic assumption beyond retaining the raw value is approved.
