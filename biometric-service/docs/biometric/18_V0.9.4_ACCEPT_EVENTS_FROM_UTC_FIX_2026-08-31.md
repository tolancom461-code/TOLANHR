# v0.9.4 accept_events_from UTC fix — 2026-08-31

## Problem found by real-device integration test

TiDB stores `accept_events_from` as a timezone-less UTC `DATETIME(6)` in the service's database session, while the ZKTeco ATTLOG timestamp is the device's local wall-clock time. v0.9.3 compared those two strings directly. On an Asia/Riyadh device this could incorrectly allow a pre-cutover event because the local clock is three hours ahead of UTC.

## Fix

- `accept_events_from` is now defined operationally as UTC.
- Device event time is converted from the configured IANA device timezone to UTC before policy comparison.
- Replay/retry no longer performs an incorrect SQL comparison between local JSON time and UTC cutoff.
- Replay/retry evaluates the same domain policy as live ingestion and marks ineligible pending/retry events `not_applicable`.
- Invalid cutoff or unconvertible device time fails canonical processing closed while keeping the safely captured ingest record durable.

## Database impact

No DDL or schema change is required.
