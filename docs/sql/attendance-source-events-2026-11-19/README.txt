الحالة والنطاق
هذه ملفات جديدة للمراجعة والتنفيذ اليدوي فقط. كتابة الملفات لا تعني تنفيذ SQL أو تفعيل الاستلام. لم تُعدّل هذه الحزمة أي ملف موجود أو schema.ts أو مسار QR أو قواعد الحضور الحالية. لا يتصل أي ملف في هذه الحزمة بقاعدة بيانات تلقائياً، ولا توجد إحالة من بدء التطبيق أو نظام الترحيلات إلى هذه الملفات.

الهدف جدول واحد جديد هو test.attendance_source_events، لحفظ استلام الحدث ومصدره وهويته الآمنة وحالة مراجعته. لا تُنشأ جداول لدورات العمل أو مهام الرواتب، ولا تُكتب أو تُعدّل سجلات attendance_events أو worker_daily_finance. لا توجد مشغلات أو إجراءات أو مفاتيح أجنبية أو شروط CHECK أو تعبئة تاريخية أو أوامر INSERT/UPDATE/DELETE/ALTER/DROP.

ترتيب المراجعة والتنفيذ اليدوي
1. افتح 01-preflight.sql وحده على الخادم المقصود. يبدأ بالأمر USE test ثم يعرض DATABASE() وإصدار الخادم والمنطقة الزمنية وخصائص المخطط. راجع هوية الخادم من جلسة الاتصال نفسها. تابع فقط إذا selected_schema يساوي test وschema_review يساوي EXPECTED_SCHEMA، وإذا existing_table_count يساوي 0. غياب صلاحية عرض بيانات information_schema سبب للتوقف والمراجعة، ولا يُعد دليلاً على غياب الجدول.
2. راجع تعريف 02-create.sql يدوياً. جميع أهداف الإنشاء مؤهلة صراحة باسم test. يتضمن الملف CREATE TABLE واحداً فقط ولا يحتوي IF NOT EXISTS؛ وجود الجدول يوقف الإنشاء حتى لا يُخفى اختلاف تعريف سابق. لا تشغّل الملفات الثلاثة دفعة واحدة. نتائج الاستعلامات في الخطوة الأولى مخصصة لمراجعة المشغّل، وليست حاجزاً آلياً يمنع تشغيل الملف الثاني على خادم آخر.
3. بعد إنشاء يدوي مصرح به، شغّل 03-verify.sql وحده. يعرض تعريف الجدول والأعمدة والفهارس وENGINE وTABLE_COLLATION من البيانات الوصفية فقط؛ لا يقرأ صفوف الأحداث أو الحضور. لا يُعد إنشاء الجدول إذناً بتفعيل موصل أو إدخال أحداث حقيقية.

عقد الجدول
id مفتاح أساسي CHAR(36) ينشئ التطبيق قيمته بصيغة UUID؛ لا يستخدم AUTO_INCREMENT. الأعمدة التعريفية source وcontent_sha256 وevent_type وstatus وdecision_code ومعرف id تستخدم ascii_bin. باقي النصوص تستخدم utf8mb4_bin. المحرك InnoDB، وجميع التواريخ ذات الدقة الزمنية تستخدم DATETIME(6).

source يحدد qr أو biometric وفق تحقق وحدة الاستلام المستقلة. source_event_id معرف ثابت للحدث لدى المصدر. القيد uq_attendance_source_key على (source, source_event_id) يخص هوية الاستلام وإعادة إرسال الحدث نفسه فقط؛ لا يحدد تكرار الحضور بين QR والبصمة ولا يضيف قاعدة للدورة أو لاختيار أول دخول أو خروج. content_sha256 يتيح لوحدة الاستلام اكتشاف اختلاف محتوى محفوظ للمعرف نفسه، ولا يضع هذا SQL سياسة لمعالجة الاختلاف.

worker_id وattendance_event_id يقبلان NULL. تحفظ أعمدة source_person_code وsource_device_id وsource_device_user_id وsource_identity_id وsource_user_name نسخة آمنة من تعريف المصدر عند الاستلام. لا تُحفظ قوالب بصمات أو صور وجه أو كلمات مرور أو رموز اتصال في هذه الأعمدة. لا توجد علاقات حذف متسلسل؛ لا يحذف تغيير عامل أو هوية أو مستخدم سجل الاستلام التاريخي من هذا الجدول.

الفهارس المتوقعة
- PRIMARY: (id)، فريد.
- uq_attendance_source_key: (source, source_event_id)، فريد.
- idx_attendance_source_worker_time: (worker_id, event_time_utc).
- idx_attendance_source_status_received: (status, received_at, id).
- idx_attendance_source_received: (received_at, id).
- idx_attendance_source_attendance: (attendance_event_id)، فهرس عادي غير فريد؛ يسمح بربط عدة سجلات مصدر بسجل حضور واحد عند المراجعة المستقبلية.

راجع في SHOW FULL COLUMNS أن الأنواع والأطوال وقابلية NULL والقيم الافتراضية والترتيب النصي تطابق 02-create.sql، وأن received_at يملك CURRENT_TIMESTAMP(6). راجع ترتيب أعمدة كل فهرس وNON_UNIQUE، وأن ENGINE يساوي InnoDB وTABLE_COLLATION يساوي utf8mb4_bin.

الأحداث والأهلية
القيم الست المعروفة هي check_in وcheck_out وbreak_out وbreak_in وovertime_in وovertime_out. وحدة الاستلام المستقلة تحفظها جميعاً. check_in وcheck_out مؤهلان للعرض على قواعد الحضور الحالية في مرحلة ربط لاحقة فقط؛ حالة الاستلام الأولية pending عند وجود عامل، وunmapped عند عدم ربط عامل. الأحداث الأربعة الأخرى حالتها review_only، ولا تصبح حضوراً أو تُشغّل حسابات مالية. SQL لا يفرض هذه القيم بقيود CHECK، لذلك يتحقق منها التطبيق.

accepted وrejected وmanual_review نتائج متاحة لإقرار معالجة مستقبلية فقط؛ لا ينفذ الجدول قرار حضور أو دورة عمل أو صرف مالي. decision_code وdecision_note وprocessed_at وattendance_event_id تسجل ذلك الإقرار مستقبلاً وفق ربط مستقل مصرح به. لا يُفعّل إعداد هذه الحزمة أي معالج انتظار أو موصل أو مسار HTTP أو تعديل لقواعد QR الحالية.

الوقت والاتصال
event_time_utc يحفظ وقت الحدث بعد التحقق منه وتطبيعه إلى UTC في وحدة الاستلام. DATETIME لا يحوّل المنطقة الزمنية بنفسه. القيمة الافتراضية received_at هي CURRENT_TIMESTAMP(6)، وتعتمد على المنطقة الزمنية لجلسة الاتصال؛ لذلك يجب أن تستخدم وحدة الاستلام UTC_TIMESTAMP(6) صراحة عند INSERT حتى يكون وقت الاستلام من قاعدة البيانات وبتوقيت UTC. لا تعتمد على القيمة الافتراضية لإثبات UTC في جلسة غير مضبوطة. processed_at عند استعماله مستقبلاً يُكتب كذلك وفق عقد UTC.

تُزوّد وحدة التخزين بمسبح اتصال صريح مع حارس لاسم قاعدة البيانات المتوقع. لا تقرأ هذه الحزمة .env أو railway_vars ولا تعيد استخدام اتصال حي أو تشغيل getDb تلقائياً. لا تُستخدم بيانات اعتماد في هذه الملفات.
